# Retrospectives

Retrospectives are required when work stalls, repeats, fails deployment, fails tests repeatedly, or
requires human correction after an agent claimed completion.

## Retrospective Record

Each retrospective should state:

- what happened;
- why the system allowed it;
- which agent, policy, script, doc, or dashboard needs improvement;
- which evidence was missing or misleading;
- what follow-up task was created.

Retrospectives are not blame records. They are control-plane feedback.
