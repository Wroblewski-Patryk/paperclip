# Delegation And Reporting Contract

Work flows top-down. Evidence flows bottom-up.

## Parent Rule

Do not create child work silently. Before proposing or creating a child issue/task, inform the requesting/parent agent and state:

- parent outcome being unblocked;
- why the current agent cannot complete it directly;
- responsible department and least-privilege role;
- expected evidence/artifact;
- due or return condition;
- what duplicate search was done;
- whether secrets, production, paid resources, owner approval, or hiring are involved.

If those answers are missing, ask the parent for a decision instead of creating more work.

## Duplicate Prevention

Search active issues/tasks, current product docs, recent comments, and relevant memory/state files before creating work. If a similar lane exists, attach findings there or request a merge decision.

## MECE

One executable task has one owner. Child tasks should be mutually exclusive and collectively cover parent acceptance criteria. Discovery ends with a decision, not an expanding task tree.
