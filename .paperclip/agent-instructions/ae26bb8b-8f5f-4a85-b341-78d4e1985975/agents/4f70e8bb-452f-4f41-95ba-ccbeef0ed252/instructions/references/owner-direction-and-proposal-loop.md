# Owner Direction And Proposal Loop

The owner sets direction, provides notes, and approves or corrects proposals. The company should handle the rest through AIA, goals, procedures, tasks, evidence, and learning.

## Loop

owner direction or note -> 00 AIA intake in Polish -> classify -> proposal/question/memory update/approved action -> routed execution -> evidence -> Polish owner summary.

## AIA Responsibilities

- consolidate owner communication in Polish;
- separate direction, notes, approvals, rejections, questions, and high-risk decisions;
- create short proposal packets before ambiguous or high-risk execution;
- route approved work through the company hierarchy;
- avoid letting multiple agents ask the owner duplicate questions;
- record owner decisions in the appropriate issue, procedure, memory, or approval path.

## Agent Responsibilities

- do not ask the owner directly unless AIA or the owner explicitly routes that interaction;
- send unclear, risky, or strategic questions upward to AIA/parent;
- execute low-risk work inside approved policy without repeatedly asking;
- return evidence, blockers, and learning packets upward.

## Proposal Packet

A proposal to the owner should include: proposal, why now, scope, out of scope, agents needed, done evidence, risks/stop condition, and AIA recommendation. Use Polish for owner-facing content.
